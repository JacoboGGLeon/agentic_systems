# API de usuario · 2.1.4.dev8

Usa `import pydantic` y `import agentic_systems as toolkit`.
**Graph define, compile prepara, run ejecuta y human_results explica.**
No hay check ni nombres alternativos para Graph en la API pública.

La conexión Bedrock puede reutilizar una sesión de la plataforma mediante
runtime(session=...). Selecciona IAM y conserva el recurso fuera de los datos;
el [contrato AWS/ADA](ADA_214.md) define conflictos, lifetime y concurrencia.
No cambia cómo se construyen Agents o Systems.

```python
import pydantic
import agentic_systems as toolkit

class Quantity(pydantic.BaseModel):
    model_config = pydantic.ConfigDict(strict=True, extra="forbid")
    value: int = pydantic.Field(gt=0)

@toolkit.tool(input_schema=Quantity, output_schema=Quantity)
def increase(request: Quantity) -> Quantity:
    return Quantity(value=request.value + 1)

capability = toolkit.skill(name="math", tools=(increase,))
graph = toolkit.Graph(Quantity)
graph.add_node("increase", increase)
graph.add_edge(toolkit.START, "increase")
graph.add_edge("increase", toolkit.END)
agent = toolkit.Agent("counter", graph=graph, skills=(capability,))
program = agent.compile()
result = program.run({"value": 4})
assert result.ok and result.data == {"value": 5}
print(result.human_results())
```

## Composición

Graph es el StateGraph original de LangGraph expuesto con un solo nombre.
Admite state_schema, input_schema, output_schema y el contexto soportado por
toolkit. add_node, add_edge y add_conditional_edges conservan su comportamiento.
No equivale a soportar todas las opciones del SDK: caching/retry/error-handler
por nodo siguen restringidos hasta integrarse con evidencia.

Agent(graph=...) organiza una capacidad; Agent(runtime=...) usa un actor de SDK.
Un grafo puede coordinar actores. System(graph=...) coordina Agents y Systems.
Environment(graph=..., records=...) coordina trabajo por episodio.
No se necesita un nivel adicional cuando no aporta una responsabilidad.

Agent/System usan run(input, timeout_s=None) o compile().run(...), además de arun.
Environment/Eval ejecutan records/cases declarados con run(timeout_s=None).
compile no ejecuta casos, records ni Tools. Los constructores validan sus datos;
la compilación comprueba la estructura declarada. No demuestra corrección de
código Python arbitrario ni sustituye Eval. El Graph es una definición; para
obtener RunResult y evidencia, compila y ejecuta su Agent/System/Environment.

## Capacidades e información

@toolkit.tool declara una operación con identidad, contrato, Context y eventos.
skill agrupa Tools e instrucciones; load_skill carga código local confiable.
La Skill no ejecuta Tools ni inserta aristas implícitas.

Con input_schema y un solo parámetro de negocio, la Tool recibe ese modelo
Pydantic completo. La firma debe reflejarlo. output_schema valida la salida.
La misma Tool tipada se prueba en ejecución directa, como nodo y con los tres
actores Python. Se conservan validación estricta y valores originales, incluso
en el adaptador OpenAI Agents: no se acepta coerción previa que oculte errores.

Tools y nodos solicitan `*, context: toolkit.Context`. Context acepta un dict
o un modelo Pydantic y fuentes. Los modelos pueden validar semántica de dominio.
Memory conserva episodios locales; State contiene canales del cálculo; lineage
registra evidencia fuera del checkpoint. No son almacenes intercambiables.

## Eval y Memory

Eval(unit, cases, checks, judge=None) ejecuta aceptación explícita, fail-fast.
Cada caso usa una vista aislada de las Memory de toolkit: parte de un snapshot
local al primer acceso y sus escrituras no modifican las instancias originales.
Dentro del mismo caso, varios episodios sí observan el progreso de esa vista.
Esto también cubre Memory.read/remember usados por funciones de nodos o Tools.
Las comprobaciones y el juez participan en la vista del caso.

El aislamiento se refiere a Memory de toolkit. No clona sesiones de SDK,
archivos, servicios ni efectos externos de las Tools. No se ofrece un sandbox
de sistema operativo ni una ejecución de negocio sin efectos.

## Resultados y controles

RunResult conserva status, ok, data, errors, usage, eventos e identidad/parentesco.
human_results() muestra operaciones de negocio, estados reales y decisiones,
con un solo ID raíz y límites de tamaño. Los wrappers técnicos se omiten de esa
vista; to_dict, trace y lineage conservan la evidencia completa.

run(timeout_s=...) comparte el plazo raíz; runtime configura proveedor/modelo,
conexión y scheduler: timeout, reintentos, backoff, concurrencia, turnos, Tools
y tokens. No hay Limits ni cuota por nodos. Un timeout es cooperativo.

pause y resume/aresume conservan trabajo completado en el mismo ejecutable y
proceso. Eval no admite pausa. Memory y continuaciones no son persistencia durable.
model_artifact/model_server declaran serving opcional; inspeccionar no inicia GPU.
