# User API · Agentic Systems 2.1.9

Use `import pydantic` and `import agentic_systems as toolkit`.
**Graph defines, compile prepares, run executes and human_results explains.**
There is no check constructor or alternate public Graph name.

A Bedrock connection can borrow a platform session through runtime(session=...). This explicitly selects IAM and keeps the resource out of business data. The [AWS/ADA contract](ADA_214.md) describes conflicts, lifetime and concurrency. Agent/System construction is unchanged.

```python
import pydantic
import agentic_systems as toolkit

class Quantity(pydantic.BaseModel):
    model_config = pydantic.ConfigDict(strict=True, extra="forbid")
    value: int = pydantic.Field(gt=0)

@toolkit.tool(input_schema=Quantity, output_schema=Quantity)
def increase(request: Quantity) -> Quantity:
    return Quantity(value=request.value + 1)

capability = toolkit.skill(name="math", tools=(increase,))
graph = toolkit.Graph(Quantity)
graph.add_node("increase", increase)
graph.add_edge(toolkit.START, "increase")
graph.add_edge("increase", toolkit.END)
agent = toolkit.Agent("counter", graph=graph, skills=(capability,))
program = agent.compile()
result = program.run({"value": 4})
assert result.ok and result.data == {"value": 5}
print(result.human_results())
```

## Composition

Graph exposes the original LangGraph StateGraph under one public name. It supports state_schema, input_schema, output_schema and toolkit context. add_node, add_edge and add_conditional_edges retain graph semantics. This does not imply support for every LangGraph option: per-node caching/retry/error-handler options remain restricted until integrated with evidence.

Agent(graph=...) organizes a capability; Agent(runtime=...) uses an SDK actor. A graph can coordinate actors. System(graph=...) coordinates Agents and Systems; Environment(graph=..., records=...) coordinates work per episode. Add a layer only when it owns a distinct responsibility.

Agent/System expose run(input, timeout_s=None), compile().run(...) and arun. Environment/Eval execute declared records/cases with run(timeout_s=None). compile does not execute cases, records or Tools. Constructors validate data; compilation checks declared structure. Neither proves arbitrary Python code correct nor replaces Eval. Execute Graph through its Agent/System/Environment to receive RunResult and evidence.

## Capabilities and information

@toolkit.tool declares an operation with identity, contracts, Context and events. skill groups Tools and instructions; load_skill executes trusted local Python. A Skill does not execute Tools or silently insert edges.

With input_schema and one business parameter, the Tool receives the complete Pydantic model; annotate that parameter accordingly. output_schema validates the result. Typed Tools retain strict input values across direct execution, graph nodes and all three Python actors; earlier coercion must not hide validation errors.

Tools and nodes request `*, context: toolkit.Context`. Context accepts a dictionary or Pydantic model and sources; models may validate domain semantics. Memory retains local episodes; State holds computation channels; lineage records evidence outside checkpoints. These stores are not interchangeable.

## Eval and Memory

Eval explicitly targets a unit, declares cases/checks and optionally a judge, and stops on failure. Each case uses an isolated toolkit Memory view, taking a snapshot at first access without writing original instances. Episodes within a case observe that view's progress. This also covers Memory.read/remember called by closures, Tools and nodes. Checks and judges participate in the case view.

Isolation applies to toolkit Memory, not SDK sessions, files, services or Tool side effects. Eval is not an operating-system sandbox or a general side-effect-free business run.

## Results and controls

RunResult retains status, ok, data, errors, usage, events and execution/parent identities. human_results summarizes business operations, actual states and decisions with one root ID and bounded size. Technical wrappers are hidden from that view; to_dict, trace and lineage retain evidence.

run(timeout_s=...) shares the root deadline. runtime configures provider/model, connection and scheduler controls: timeout, retries, backoff, concurrency, turns, tools and tokens. There is no public Limits object or node quota. Timeouts are cooperative.

pause and resume/aresume preserve completed work in the same compiled program and process. Eval does not support pause. Memory and continuations are not durable persistence. model_artifact/model_server declare optional serving; inspection does not start a GPU process.
