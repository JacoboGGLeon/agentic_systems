# Checkpoint 1.1.4 - Runtime and Provider Substitution Contract

Status: implemented and validated locally.

## Initial State

- Canonical Provider selection existed without a shared substitution contract.
- Adapters normalized results but did not expose capability profiles.
- Sync fallbacks and partial usage reporting were not machine-readable as
  degradations.
- Tests covered adapters independently rather than through one conformance
  evaluator.

## Decision

Define substitution at the observable `RunResult` boundary. Require common
result, identity, Tool evidence, failure, validation, and serialization
semantics. Model operational differences as explicit optional capabilities
instead of promising impossible equivalence.

## Changes

- Added immutable capability declarations and Provider profiles.
- Added `ProviderProfile.check(...)` with strict or permissive degradation.
- Added `ProviderConformanceReport` and a common evaluator.
- Exposed profiles from all four primary adapter classes.
- Added one parametrized conformance suite for success and failure paths.
- Added the normative substitution contract and ADR 0006.

## Compatibility

- Existing runtime names and execution methods are unchanged.
- Existing top-level API exports are unchanged.
- New symbols are exposed through the existing advanced `providers` namespace.
- Profiles describe adapter behavior; they do not require optional SDK imports
  or live credentials.
- No claim is made that generated text, latency, usage, cost, or model quality
  are equal across Providers.

## Invariants

```text
Agent execution returns normalized RunResult
result.engine identifies the actual canonical Provider
executed Tools remain structured evidence
failed execution remains structured and cannot report false success
Agent Contract validation is Provider-independent
public result and conformance data serialize to JSON
degraded and unsupported optional capabilities are explicit
```

## Risks Pending

- The suite uses controlled transports and does not certify live credentials or
  endpoint availability.
- Streaming and cooperative cancellation remain unsupported at the common
  Agent result boundary.
- Framework substitution is distinct from Provider substitution.
- Domain-level semantic equivalence still requires application-specific
  Contracts and evaluation cases.
