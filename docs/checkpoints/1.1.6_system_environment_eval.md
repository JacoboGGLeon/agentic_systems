# Checkpoint 1.1.6 - Systems, Environments, and Evals

Status: implemented and validated locally.

## Initial State

- System, Graph, Environment, and Eval responsibilities were described but
  their mutable state and lifecycle ownership overlapped in practice.
- Environment accepted a seed without owning an inspectable RNG.
- Episode reports omitted seed evidence.
- `run_eval` implied determinism for arbitrary Agents and Providers.
- Eval aggregate fields were not checked against case results.

## Decision

Separate composition, transition, episode, and verification ownership; make
episode randomness local and inspectable; require explicit Eval
reproducibility classification; and reject contradictory reports.

## Changes

- Added normative ownership and lifecycle semantics.
- Added Environment-owned `seed` and local `rng`.
- Projected seed into episode Graph state, info, render, and summary.
- Added public `EvalReproducibility` with deterministic, seeded, and
  non-deterministic classifications.
- Added schema/version and reproducibility evidence to `EvalReport`.
- Added aggregate invariants with clear validation errors.
- Added ADR 0008 and focused contract tests.

## Compatibility

- Existing Environment construction and step tuple remain unchanged.
- Record order is unchanged; setting a seed does not imply shuffling.
- Existing Eval methods remain compatible through optional keyword arguments.
- Existing valid EvalReport constructors remain valid with additive defaults.
- Serialized Eval reports gain additive schema and reproducibility fields.
- The default classification is conservative and does not promise remote-model
  equivalence.

## Invariants

```text
System composition state is not Graph transition state
Graph transition state is not Environment episode ownership
Environment state is not Eval scoring state
same Environment seed resets the same local RNG sequence
Environment seed never mutates process-global random state
seed alone does not imply deterministic Provider or Tool behavior
Eval aggregates derive exactly from case results
non_deterministic reports never promise replayability
```

## Risks Pending

- Remote Provider seed support is capability-specific and not normalized.
- External Framework concurrency and persistence may add uncontrolled ordering.
- Replaying network and Tool side effects requires fixtures or an evidence
  capture mechanism outside this checkpoint.
- Environment initial memory is caller-provided and mutable; callers must
  provide equivalent episode inputs for replay.
