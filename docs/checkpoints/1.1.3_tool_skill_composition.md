# Checkpoint 1.1.3 - Tool and Skill Composition

Status: implemented and validated locally.

## Initial State

- Skill detected duplicate Tool names only within one package.
- AgenticSystem and neutral runtime registries assigned by name and could
  silently replace an existing definition.
- Composition precedence and provenance were not inspectable.
- No ordinary API combined runtime Skills as packages.

## Decision

Use scoped public names as identity, reject different definitions by default,
allow only explicit `keep` or `replace`, treat the same definition as idempotent
reuse, and expose every resolution as structured composition evidence.

## Changes

- Added internal conflict-policy normalization shared by registries.
- Added `Tool.identity` and `Skill.identity`.
- Added `Skill.compose(...)` and `Skill.composition()`.
- Added explicit conflict handling to AgenticSystem, Toolkit, and neutral runtime
  Tool registration.
- Added `AgenticSystem.composition()` and composition data to `inspect()`.
- Added normative laws and ADR 0005.
- Added 15 composition regression tests.

## API Affected

All additions are backward-compatible for non-colliding calls. Existing calls
may add `on_conflict="keep"` or `on_conflict="replace"` when an override is
intentional. Calls that depended on a silent last-wins collision now fail with a
migration message.

## Compatibility

- Top-level public imports are unchanged.
- Tool and Skill constructors remain compatible.
- Tool and Agent execution contracts are unchanged.
- Filesystem LoadedSkill behavior remains separate and compatible.
- Composition report fields are additive.
- No Provider, Framework, schema version, or serialization envelope changes.

## Invariants

```text
visible identity == selected executable identity
different definitions never collide silently
keep selects existing
replace selects incoming
same definition is reusable and idempotent
Skill composition does not execute
resolution is ordered and JSON-inspectable
```

## Risks Pending

- Contract compatibility between different Tool schemas is deferred.
- Removal/unregistration semantics are not introduced.
- LoadedSkill/runtime Skill unification remains deferred.
- Provider conformance is Checkpoint 1.1.4.
