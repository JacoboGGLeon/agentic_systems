# Checkpoint 1.1.2 - RunResult Invariants

Status: implemented and validated locally.

## Delivered

- Normative rules in `docs/RUNRESULT_INVARIANTS.md`.
- `RunResult.apply_validation(...)` for consistent validation status and errors.
- `RunResult.check_invariants()` for non-mutating structural validation.
- `RunResult.raise_if_inconsistent()` for actionable failure messages.
- Shared recovered/unresolved Tool failure classification.
- Regression tests under `tests/contracts/`.

## Compatibility Decision

The checkpoint does not add or remove RunResult fields and does not change the
run or trace schema versions. `final`, `data`, and `text` remain separate
projections. Partial failures remain legal when policy permits them.

Failed required validation now always forces overall failure and contributes
structured errors. Failed Tool errors gain additive recovery metadata. Both
changes remove contradictions without rejecting valid historical result shapes.
