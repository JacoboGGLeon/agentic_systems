# AWS y ADA opcional · 2.1.4.dev8

El runtime Bedrock existente acepta una sesión externa. La aplicación conserva
la misma gramática de Agent, System y Graph. El complemento ADA es un paquete
independiente; no se instala con all y no existe otro constructor de runtime.

```python
import agentic_systems as toolkit

# supplied_session ya fue preparada por la plataforma; no pegues sus claves.
aws = toolkit.runtime(
    provider="bedrock-runtime",
    model="modelo_habilitado_en_tu_region",
    session=supplied_session,
)
agent = toolkit.Agent("worker", runtime=aws)
program = agent.compile()  # prepara; no prueba IAM ni ejecuta el modelo
```

## Contrato de la sesión prestada

- Solo Bedrock admite session=. Se necesita el protocolo boto3 client y una
  región válida; no se resuelven credenciales durante la construcción.
- La sesión selecciona IAM explícitamente, incluso si existe un bearer global.
  api_key/endpoint y una región contradictoria se rechazan.
- Native, OpenAI Agents y Strands usan la sesión del runtime. Las regresiones
  comprueban SigV4 en los tres SDK con transporte simulado; no acreditan IAM real.
- No se extraen claves ni se congela el mecanismo de credenciales del proveedor.
  El SDK no modifica AWS_EC2_METADATA_DISABLED globalmente; el harness de pruebas
  puede configurarlo en su propio proceso para bloquear metadatos offline.
- El recurso queda excluido de repr, configuración JSON y resultados. No debe
  entrar en Context, estado ni Memory. Un JSON no restaura una conexión viva.
- El propietario conserva el lifetime. El toolkit no cierra la sesión prestada.
- Las invocaciones del toolkit que comparten una sesión se serializan con el
  tiempo restante del plazo raíz. Esto no hace thread-safe usos externos y no
  permite trasladar el recurso a otro proceso.

## Complemento ADA

La distribución local agentic-systems-ada ofrece diagnóstico read-only:

```python
import agentic_systems_ada as ada

report = ada.diagnose(session=supplied_session)
assert report["services_checked"] is False
```

El CLI agentic-systems-ada doctor imprime JSON con flags de presencia. No consulta
STS ni IMDS, no resuelve credenciales, no borra variables y no configura roles,
CA, proxies o Artifactory. Una pareja estática sin session token puede ser válida;
el diagnóstico describe la ambigüedad, no la declara una credencial inválida.

ADA Studio y su wallet son un entregable posterior, fuera de este complemento.
