# AWS and optional ADA · 2.1.9

The existing Bedrock runtime can borrow an external session. Agent, System and Graph grammar stays unchanged. ADA is a separate diagnostics package, not installed by all, and does not add another runtime constructor.

```python
import agentic_systems as toolkit

# supplied_session was prepared by the platform; never paste credentials.
aws = toolkit.runtime(
    provider="bedrock-runtime",
    model="model_enabled_in_your_region",
    session=supplied_session,
)
agent = toolkit.Agent("worker", runtime=aws)
program = agent.compile()  # prepares; does not test IAM or run inference
```

## Borrowed-session contract

- Only Bedrock accepts session=. A boto3 client protocol and valid region are required; construction does not resolve credentials.
- Supplying a session explicitly selects IAM even when a global bearer exists. api_key/endpoint and conflicting regions are rejected.
- Native, OpenAI Agents and Strands use the runtime session. Regression tests check SigV4 with simulated transport, not real IAM access.
- No credentials are extracted or provider credential mechanisms frozen. The SDK does not globally change AWS_EC2_METADATA_DISABLED; the test harness may set it in its own process to block offline metadata access.
- The resource stays out of repr, JSON configuration, results, Context, state and Memory. JSON cannot restore a live connection.
- The owner controls lifetime; the toolkit does not close a borrowed session.
- Toolkit invocations sharing a session are serialized within remaining root time. This does not make external use thread-safe or allow moving the resource across processes.

## ADA add-on

The separate agentic-systems-ada distribution provides read-only diagnostics:

```python
import agentic_systems_ada as ada

report = ada.diagnose(session=supplied_session)
assert report["services_checked"] is False
```

agentic-systems-ada doctor prints presence flags as JSON. It does not call STS/IMDS, resolve credentials, clear variables or configure roles, certificates, proxies or Artifactory. Static credentials without a session token can be valid; diagnostics describe ambiguity rather than declaring them invalid.

The bedrock extra installs AWS SDKs. The add-on is separate; an ada extra merely duplicating bedrock would provide neither independence nor credentials. Real AWS/ADA IAM requires verification in each prepared environment. ADA Studio and its wallet are outside this add-on.
