# Architecture Decision Records

These records preserve accepted architectural decisions. They explain why a
boundary exists; current user behavior remains defined by the API, contracts,
tests and release documentation.

| ADR | Decision |
|---|---|
| [0005](0005-skill-composition-and-conflicts.md) | Skill composition and conflict handling |
| [0006](0006-runtime-provider-substitution.md) | Runtime and Provider substitution |
| [0007](0007-framework-graph-boundary.md) | Framework and Graph ownership boundary |
| [0008](0008-system-environment-eval-ownership.md) | System, Environment and Eval ownership |
| [0009](0009-execution-context-remains-conceptual.md) | Execution Context remains conceptual |
| [0010](0010-static-system-inspection.md) | Static System inspection |

ADRs are historical decision records. If an ADR conflicts with current
behavior, the current contract wins and the ADR must be marked superseded.
